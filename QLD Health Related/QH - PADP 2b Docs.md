| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| 1   | Arrays with useful data are flattened into separate views (not all arrays are flattened; can be a single column, related columns group, or a LinkedGroup). | Pass        |
| 2   | All **dates** converted to **DATE** type; timezone is **AEST**.                                                                                            | Pass        |
| 3   | All **times** converted to **HH:MM:SS** format.                                                                                                            | Pass        |
| 4   | Where there are related **date** and **time** columns, a **datetime** column is created.                                                                   | Pass        |
| 5   | Composite `<Table_id>` split into individual elements from `_metadata.ID_elements`, prefixed with `id_` (e.g., `id_patient_no`, `id_referral_number`).     | Pass        |
| 6   | Composite **filed** and **audit** columns are split into individual data elements.                                                                         | Pass        |
| 7   | Column definitions are added in **Unity Catalog**.                                                                                                         | Pass        |
| 8   | **Unflattened base views** are named `<base_table>__v` (e.g., `admissions__v`).                                                                            | Pass        |
| 9   | Unflattened base views include all **unflattened** columns plus relevant transformations.                                                                  | Pass        |
| 10  | Granularity of unflattened base views matches the base table; `<uid>` is unique.                                                                           | Pass        |
| 11  | **Flattened views** are named `<base_table>__<flattened_field_name>_v`; for LinkedGroup, the name aligns with fields in the flattened view.                | Pass        |
| 12  | Flattening produces multiple rows (and potentially columns) per base-table record.                                                                         | Pass        |
| 13  | `<uid>` is used to join back to base view/table.                                                                                                           | Pass        |
| 14  | Combination of `<uid>` and `<pos>` is the unique identifier in flattened views.                                                                            | Pass        |


```sql
WITH bank_exploded AS (

  SELECT

    b.table_id,

    b.hbcis_instance,      

    b.date,

    b.LinkedGroup1.amount[0] AS amount_0,

    tn.txn_no

  FROM cbi_ods_pat.hbcisprod.bank b

  LATERAL VIEW explode(b.transaction_no) tn AS txn_no

)

SELECT b.table_id as Receipt_Number,

       t.date AS Transaction_Date,

       p.table_id as Patient_Number,

       p.family_name,

       p.given_names,

       t.LinkedGroup1[0].account_class AS account_class,

       b.date AS Posting_Date,

       b.amount_0 as Amount

FROM bank_exploded b

JOIN cbi_ods_pat.hbcisprod.transactions t

  ON t.table_id = b.txn_no

  AND t.hbcis_instance = b.hbcis_instance

JOIN cbi_ods_pat.hbcisprod.patients p

  ON p.table_id = substring(b.txn_no, 1, locate('-', b.txn_no) - 1)

  AND p.hbcis_instance = b.hbcis_instance

LIMIT 5;
```
